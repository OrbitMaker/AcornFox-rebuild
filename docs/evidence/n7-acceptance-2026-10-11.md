## 5. 公网控制台（ADR-0016）

| 检查 | 结果 |
|---|---|
| 已备案域名：`enable` 后按提示加一条 A 记录 | 约 4 分钟内自动验证通过并开通；HTTPS 证书在开通后约 2 分钟签发（测试机连 Let's Encrypt 正式接口有超时，Caddy 自动重试） |
| 用生成的密码登录、退出 | 通过；Cookie 带 Secure 与 HttpOnly，响应带 HSTS；退出后回到登录页 |
| 连续输错 5 次 | 被锁定，正确密码也提示“尝试次数过多，请 1 分钟后再试” |
| 重启 Caddy | 30 秒后路由自动恢复，应用不受影响 |
| 升级后配置保留 | 多次升级后 `status` 均显示已开启、HTTPS 正常 |
| 未备案域名（用 sslip.io 这类公共解析服务，指向测试机且未备案） | 诊断 `icp_blocked`：“该域名未备案，国内服务器无法使用”；未开通，原有配置不受影响 |
| 安全组未放行 80/443 | 在服务器上用 `--local` 执行，诊断为 80 端口超时，提示到安全组放行 80 和 443。从开着代理软件的电脑上执行时，同一情形显示为“连接被断开”，已把这条提示补充为同时检查安全组 |
| `disable` | 入口立即失效；再次 `enable` 直接复用证书 |

旧网关 `acornfox-public-console` 所在的原测试机已被释放，新测试机直接使用本功能，旧网关的两个目录已删除（从未提交）。

## 6. 实测发现并修复的问题

| 问题 | 修复提交 |
|---|---|
| **公网控制台在真实浏览器里无法登录**：登录页 `Referrer-Policy: no-referrer` 使表单提交的 Origin 为 `null`，被来源校验拒绝；单元测试手工设置了 Origin，没有发现 | `8ad5bd1a` |
| **Windows 版 CLI 无法构建**：CLI 经公网控制台包间接引用了只能在 Unix 上编译的 `internal/state`，发版构建时发现 | `eacafd1e` |
| 添加附加服务时等待就绪的 120 秒包含了拉镜像的时间；经加速站拉 Redis 用了 3 分多钟，部署被误判为“没有就绪” | `ef870038` |
| 诊断卡“添加数据库并重新部署”：从未上线的应用不会重新部署；有旧版本时又重新部署旧版本 | `2446658b` |
| 失败部署的镜像被立即清理，上一条的重新部署去公网拉 `sha256:` 镜像而失败；现在保留最近一次失败部署的镜像 | `9ce36f9d` |
| 构建时镜像加速站返回 502，诊断让用户修改 Dockerfile | `58b71994` |
| 控制台离开详情页时，轮询请求 `/v1/apps/null/deployments` | `c7f12671` |
| 重新部署切换容器的瞬间，应用指标接口返回 503，浏览器控制台报错 | `f838d111`（v0.3.1） |
| 公网控制台“连接被断开”的提示只说未备案 | `fa6d74c3` |
| `acornfox help` 不存在 | `58b71994` |
