# 网页控制台设计

日期：2026-10-10 [cc]。状态：已确认（负责人同意整体思路）。取代 `acornfox-rebuild-migration-plan.md` 第 3.8 节的“桌面 + 底部工具栏 + 弹出窗口”形式；3.8 节的原则继续有效。视觉规范见 [brand.md](brand.md)。

## 1. 结构

去掉“桌面 + 底部 Dock + 弹出窗口”，改为**顶栏 + 页面**：

| 页面 | 内容 |
|---|---|
| 我的应用（首页） | “需要处理”置顶（最多三条，每条可一键复制给 AI）；应用卡片：状态、版本、访问地址、运行开关；没有应用时给出三种开始方式 |
| 应用中心 | 浏览与一键安装现成应用（见 `docs-private/app-center-and-ops-system-plan.md`）。目录服务上线前显示“即将开放”与首批应用预告 |
| 服务器 | 主机 CPU、内存、磁盘、负载、运行时长；各应用占用；版本与升级、访问方式 |
| 设置 | 外观、连接 AI 工作台、修改应用配置的方式、登录会话 |

- 顶栏常驻：标志、服务器名、四个页面、“让 AI 帮忙”。手机宽度下四个页面改为底部标签栏。
- 应用详情是独立页面（地址 `#/app/<名称>/<标签>`），六个标签：**概览 / 日志 / 版本记录 / 配置 / 数据库 / 域名**。
- 保留 3.8 节原则：首页只放应用；有问题才出现；每个问题可一键复制给 AI；细节放下一层。
- 应用启停 = 卡片上的开关。停止前确认，确认框默认焦点在“取消”。
- 部署失败时诊断卡置顶，明确“旧版本仍在服务”，给出“复制给 AI”。

## 2. 数据库（附加服务）

- **按需自动安装，不默认安装**：
  - 应用中心的应用：模板声明需要的数据库，安装时自动带上；
  - 自己的项目：诊断发现缺少数据库连接时，诊断卡给出“添加 X 并重新部署”。
- 仍为每个应用一套容器：应用专用网络、不发布端口、凭据以密钥注入、删除默认保留数据卷。
- 控制台“数据库”标签：每种数据库一个开关。打开即添加，已上线应用自动重新部署；关闭时确认框默认保留数据，可勾选一并删除。PostgreSQL 与 MySQL 都提供 `DATABASE_URL`，同一应用只能有其一。
- 两种来源：
  - 本机容器：从版本白名单选择，创建后不能换版本（换版本需导出再导入，首发不做迁移）；
  - 外部数据库：填连接地址，存为密钥注入 `DATABASE_URL` / `REDIS_URL`。目前用 `acornfox env set DATABASE_URL --secret`，控制台只给出说明。

## 3. 版本白名单（依据官方支持周期，2026-10-10 核实）

| 数据库 | 白名单 | 默认 | 说明 |
|---|---|---|---|
| PostgreSQL | 15、16、17、18 | 16（现有） | 14 于 2026-11-12 停止支持，不列入 |
| MySQL | 8.4 LTS、9.7 LTS | 8.4（现有） | 8.0 已于 2026-04-30 停止支持；老项目需要旧版本时走外部数据库 |
| Redis | 7.4、8.2 | 7（现有标签，建议固定到 7.4） | 做云上商用版前需确认 Redis 许可证 |

实现时需要：执行器镜像校验从三个固定镜像改为白名单；核对 Docker 官方镜像标签；附加服务表记录所选版本与来源（追加迁移）。**截至本文，控制台只能添加默认版本**，版本选择待后端支持。

## 4. 实现约束（沿用）

- 不依赖框架；不使用 `innerHTML`；不内联脚本与样式属性；不加载外部资源（字体随控制台打包）。
- 轮询不打断用户的选择、焦点与滚动；日志跟随可暂停。
- 凭据、连接串、密钥值不进入页面。
