How it works

部署、失败、修复，都在一次对话里完成

AcornFox 的输出为 AI 而写：每次失败都给出阶段、原因、建议和日志片段，AI 不用猜。

说一句话

AI 分析项目、生成 Dockerfile，调用 acornfox deploy 打包上传。

服务器构建

在你的服务器上构建镜像、启动容器，健康检查通过才切换流量。

失败给诊断

旧版本继续服务；返回结构化诊断，交给 AI 修改后重新部署。

上线可访问

立即得到 http://IP:端口；绑定已备案域名后自动 HTTPS。

Features

一台服务器需要的，都已经备好

状态记在 AcornFox，运行交给 Docker：AcornFox 重启或升级时，你的应用照常运行。

三种来源，一条命令

本地目录（Dockerfile）、公开 Git 仓库或现成镜像，acornfox deploy 即可。

结构化失败诊断

构建、启动、健康检查、路由逐阶段判定，附建议与日志片段，可直接交给 AI。

PostgreSQL · MySQL · Redis

acornfox add postgres 自动注入连接变量，端口不对外暴露，删除默认保留数据卷。

完整生命周期

停止、启动、重启、重新部署、回滚、删除；升级前自动备份，失败自动回退。

日志、指标与控制台

实时跟随日志，查看主机与容器的 CPU、内存；acornfox open 打开网页控制台。

HTTPS 与国内优化

已备案域名自动签发证书；国内服务器走 Gitee 镜像与云厂商内网源，未备案域名给出提示。

Architecture

简单的三层，权限分开

CLI 经 SSH 连接服务器，不开放额外端口；server 不持有 Docker 权限，runner 只接受类型化请求。

Get started

准备一台 Linux 服务器，开始吧

Ubuntu 24.04 / 22.04 / 20.04 或 Debian 12 / 11，amd64 / arm64。云服务器请在安全组放行 TCP 18810-18899，绑定域名再放行 80、443。

$

然后：acornfox target add my-server --ssh root@服务器IP，再在项目目录运行 acornfox deploy。完整步骤见 安装指南。
