在 AI 工作台里说一句话，应用就跑在你自己的服务器上

AcornFox 在你的 Linux 服务器上构建、上线应用，管好数据库、域名和 HTTPS。部署失败时给出结构化诊断，AI 读完就能接着修。

把这句话发给 Claude Code、Codex 等 AI 工作台：

请安装 AcornFox Skill：下载 https://acornfox.com/skill/SKILL.md ，保存为你 skills 目录下的 acornfox/SKILL.md（Claude Code 是 ~/.claude/skills，Codex 是 ~/.codex/skills），然后按这个 Skill 把当前项目部署到我的服务器。

Skill 会判断你的电脑和服务器在国内还是海外，选对下载源，装好命令行工具与服务端，然后部署。你只需要一台能 SSH 登录的 Linux 服务器。也可以手动安装。

开源AGPL-3.0不中断升级时应用照常服务

部署、失败、修复，都在一次对话里完成

AcornFox 的输出是写给 AI 看的：每次失败都说清是哪一步、为什么、该改哪里，AI 不用猜。

  1. 说一句话

    AI 读懂你的项目，生成 Dockerfile，调用 acornfox deploy 打包上传。

  2. 在你的服务器上构建

    构建镜像、启动容器，健康检查通过才切换流量。

  3. 失败给诊断

    旧版本继续服务；诊断交给 AI，改完重新部署。

  4. 上线可访问

    立即得到 http://IP:端口；绑定已备案域名后自动 HTTPS。

出了问题，旧版本照常服务，诊断一键交给 AI

新版本没通过健康检查时，流量不会切过去。控制台把诊断放在最上面：停在哪一步、关键日志、建议怎么改。缺数据库时，一个按钮加上并重新部署。

一台服务器需要的，都已经备好

状态记在 AcornFox，运行交给 Docker，访问交给 Caddy。AcornFox 重启或升级时，你的应用照常运行。

三种来源
本地目录（含 Dockerfile）、公开 Git 仓库或现成镜像，都是 acornfox deploy。
数据库按需装上
PostgreSQL、MySQL、Redis 每个应用独立一套，连接地址以密钥注入，端口不对外开放，删除时默认保留数据。
一个开关管启停
停止、启动、重启、重新部署、回退到上一版；升级前自动备份，失败自动回退。
日志与资源
实时跟随日志，看主机和每个应用的 CPU、内存；acornfox open 打开网页控制台。
域名与 HTTPS
已备案域名自动签发证书；未备案时给出明确提示，IP:端口 照常访问。
国内网络优化
国内服务器走 Gitee 镜像与云厂商内网源，下载慢时自动换源。
只走 SSH
命令行经 SSH 连接服务器，不开放额外端口；控制台默认只在服务器本机监听，acornfox open 经 SSH 隧道打开；需要时可绑定自己的域名开启公网访问，自动 HTTPS、密码登录。
权限分开
服务端不持有 Docker 权限，执行器只接受类型化请求，凭据只写不读。

准备一台 Linux 服务器，开始吧

Ubuntu 24.04 / 22.04 / 20.04 或 Debian 12 / 11，amd64 或 arm64，建议 2 核 2 GB 以上。云服务器请在安全组放行 TCP 18810–18899；绑定域名再放行 80、443。

推荐把上面那句话发给 AI。也可以手动安装，先在你的电脑上装命令行工具：

curl -fsSL https://gitee.com/VIP13390/AcornFox-rebuild/raw/main/scripts/install/install-cli.sh | bash
curl -fsSL https://github.com/OrbitMaker/AcornFox-rebuild/releases/latest/download/install-cli.sh | bash

然后 acornfox target add my-server --ssh root@服务器IP，再在项目目录运行 acornfox deploy。服务端安装与升级见安装指南。
